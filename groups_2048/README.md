# 위수 2048 군: 정확히 확정된 부분과 하한 (2차 진행)

**전체 개수 f(2048)는 여전히 미해결이다.** 공개 문헌에도 정확한 값이 없다.
이번 작업에서는 다음을 엄밀하게 계산했다. 각각 서로 다른 방법으로 교차 검증했다.

1. 최소 생성원 수(rank) **1, 2, 3, 9, 10, 11**인 위수 2048 군의 정확한 개수
2. f(2048) = (직접분해 가능) + (분해 불가능 · P₃=1) + (분해 불가능 · P₃≠1) 분해의
   앞의 두 항 전체와 마지막 항의 일부
3. 강화된 하한 **f(2048) ≥ 1,774,274,818,661,974** (이전 하한보다 15,993,667 큼)

- P₃=1 열은 `e_n.py`의 Burnside 계산(rank별 출력 `e_n_11_by_rank.txt`)이다.
- rank ≤ 3인 위수 2¹¹ 군은 자동으로 P₃≠1이다. P₃=1이면 |G| ≤ 2^{d+d(d+1)/2}이기 때문이다.
- rank 10, 11 군은 |Φ(G)| ≤ 2라서 자동으로 P₃=1이다.

참고로 위수 2ⁿ의 2-생성 군 수(OEIS A170900, 현재 2⁹까지 등재)의 다음 두 항은
2¹⁰: **9,121**, 2¹¹: **47,486**이다. 3-생성 군은 2¹⁰: **780,707**, 2¹¹: **15,958,121**이다.

## 3. 방법과 검증

### (a) rank 2, 3: p-군 생성 트리 전수 탐색
- ANUPQ `pq`(GAP 4.14.0, anupq 3.3.1)의 p-group generation으로 C₂ᵈ의 모든 자손을
  위수 2¹¹까지 센다. 각 군은 정확히 한 부모(G/P_c(G))의 직계 자손이므로
  직계 자손 수의 합이 곧 군의 수다.
- `pq/order_bound_leaf.patch`: 위수가 상한에 도달한 자손은 다시 부모가 될 수 없다.
  그래서 자기동형군 계산과 파일 저장을 생략하도록 `pq`를 수정했다.
  개수는 궤도 수로 정해지므로 바뀌지 않는다. 원본 대비 디스크 사용량이 4 GB 이상에서 수백 MB로 줄었다.
- rank 3은 class-2 부모별 부분 트리를 병렬로 돌렸다(`pq/run_subtrees.py`).
  같은 방식으로 2⁹까지 돌린 결과가 전체 순차 실행과 정확히 같았다.
- 검증:
  - SmallGroups 라이브러리: 위수 2⁹까지 rank별 개수가 일치한다. 2⁹에서 rank 2 = 2,043, rank 3 = 58,859.
  - OEIS A170900: 3, 8, 19, 53, 162, 540, 2043이 일치한다.
  - GAP 측 트리 탐색(`gap/tree.g`): `PqDescendants`와 AutPGrp 자기동형군을 쓰는 다른 경로다.
    rank 2는 2¹¹까지 47,486으로 일치하고, rank 3은 2¹⁰까지 780,707로 일치한다.

### (b) rank 9: 2-중복자(multiplicator) 위의 Burnside 계산
- rank 9, 위수 2¹¹, P₃≠1인 군 G는 |Φ(G)|=4, |P₃(G)|=2다.
  따라서 G/P₃(G) = H는 |Φ(H)|=2인 rank 9 군이다.
  이런 H는 F₂⁹ 위 0이 아닌 이차형식의 동치류와 대응하며 13개다(`gap/qf.g`).
- G는 H의 step-1 직계 자손이다. 그 수는 2-중복자 M(H)의 초평면 U 중
  핵(nucleus) N을 포함하지 않는 것들의 Aut(H)-궤도 수다.
  Burnside로 (1/|A|) Σ_a (2^{dim Fix_M(a)} − 2^{dim Fix_{M/N}(a)})를 계산한다(`gap/step1.g`).
- 13개 중 핵이 0이 아닌 것은 D₈×C₂⁷과 C₄×C₂⁸ 두 개뿐이다. 나머지는 terminal이다.
- 2-덮개 H*는 H의 d-생성 fp 표현에서 `PqPCover`로 만든다. H*의 `FamilyPcgs` 앞쪽 |H|개
  생성원이 H의 pc 관계식을 그대로 만족하는지 직접 확인한다. 그러면 나머지 생성원(tail)이
  2-중복자 M이고, 자연 사상은 지수 벡터 절단이다.
  M이 중심의 초등 아벨군인지도 단언으로 확인한다.
- 자기동형 α의 작용은 다음처럼 계산한다. α(xᵢ)의 아무 lift를 잡고, M의 생성원을 정의 생성원의
  단어로 한 번 써 둔 뒤 그 단어를 lift에 대입한다. H*의 상대 자유성 때문에 이 계산이 정당하다.
  그래도 매 대표원마다 준동형 성질을 무작위 원소로 점검한다.
- 검증:
  - 같은 계산으로 rank d = 3…7(위수 2^{d+2})을 구하면 9, 14, 18, 23, 27이 나온다.
    SmallGroups의 해당 값과 정확히 일치한다.
  - 부모별 값도 d ≤ 7에서 `pq`의 직접 자손 계산과 일치한다.
  - 서로 다른 난수 시드 두 개로 같은 값이 나온다.
  - 결과: rank 8(위수 2¹⁰)은 32, rank 9(위수 2¹¹)는 36.

### (c) 분해 가능 군의 rank별 계수
- `indecomposable_by_rank.py`: Σ a_{n,d} xⁿ yᵈ = Π (1 − xⁿ yᵈ)^{−b_{n,d}}를 역산한다.
  SmallGroups에서 `DirectFactorsOfGroup`으로 직접 센 2⁵~2⁷의 분해 불가능 군 수와
  모든 rank에서 일치함을 확인했다.

### (d) P₃=1 계산의 rank별 검증
- `e_n.py`의 rank별 값은 SmallGroups 2⁹(1천만 개 군, rank·p-class 정렬)과
  모든 rank에서 일치한다: 1, 6,709, 5,829,109, 2,948,829, 1,112, 12, 1.

## 4. 남은 것: 정확한 항등식

D = 49,497,988,786(직접분해 가능한 군 전체)과
h₁₁ = e₁₁ − D_good = 1,774,225,304,679,516(분해 불가능 · P₃=1)은 정확히 알려져 있다.
따라서

    f(2048) = 1,774,274,818,661,974 + X

이다. 여기서 X는 rank 4~8이면서 P₃(G)≠1이고 직접분해 불가능한 위수 2048 군의 수이며,
이것이 남은 유일한 미지수다. 이 계층은 2-중복자의 계수가 커서(수십)
p-group generation으로는 직접 셀 수 없다.

- 따라서 전체 대표원 목록과 전체 완전성의 Lean/Coq 형식 증명도 여전히 불가능하다.

결과 데이터: `results/` (rank 2 개수, rank 3 부분 트리별 개수, rank 8·9 Burnside 결과).

## 5. 재현

```sh
python3 e_n.py 11                  # P₃=1, rank별 (수십 분)
python3 euler.py                   # 분해 가능 군
python3 pq/mkin.py 2 11 > in && pq < in > out    # rank 2 (패치된 pq, 약 1분)
python3 pq/run_subtrees.py 3 11 3 run11          # rank 3 (3코어 병렬 약 1.5시간)
gap -q -b gap/rank_n_minus_2.g    # rank 3~9의 P₃≠1 (gap/ 디렉터리에서)
python3 bound.py --n3 780707 15958121 --c 32 36
```

- `pq/run_subtrees.py`와 `pq/mkin.py`는 패치된 `pq` 실행 파일과 GAP 경로(`ANUPQ_GAP_EXEC`)를
  스크립트 상단에서 지정한다. 환경에 맞게 고쳐서 쓴다.
- 주의: `PqPCover`가 돌려준 군에는 처음에 `Pcgs`가 지정되어 있지 않다. `PCentralSeries`를 먼저
  계산하면 다른 pcgs가 설치되어 `Pcgs(cover){[1..d]}`가 정의 생성원이 아니게 된다.
  개발 중 이 때문에 단언이 실패한 적이 있다. 최종 코드는 `FamilyPcgs`를 쓰고 관계식으로 확인한다.
- rank 8, 9는 부모 하나가 수 분~수십 분 걸리므로 `gap/one_parent.g.in`으로 부모별로 돌릴 수 있다.
