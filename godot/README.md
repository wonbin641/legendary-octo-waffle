# Yarr! 07 (야르 07) · Godot 4판

브라우저판(`../src`, Three.js)을 Godot 4.7로 옮긴 것입니다. 브라우저판은 지우지 않았고 그대로 배포됩니다. Godot판은 `../godot-web/`(GitHub Pages의 `/godot-web/`)에 올라갑니다.

- 엔진: Godot 4.7, GDScript, Compatibility 렌더러(웹용).
- 충돌과 길 찾기는 Godot의 물리 엔진이 아니라 브라우저판의 코드를 그대로 옮긴 것입니다(`scripts/phys.gd`). 조작 느낌과 적의 움직임이 같아야 하기 때문입니다.
- 지도는 브라우저판과 같은 난수를 같은 순서로 써서 만듭니다(`scripts/world.gd`). 컨테이너, 상자, 가로등이 같은 자리에 섭니다.

- 화면 그리는 방식(three.js r128과 같은 결과가 나오게): ACES 톤 매핑을 브라우저판 곡선에 맞추고(노출 ÷0.6÷1.8, 흰점 14.26), 안개는 톤 매핑이 끝난 화면 위에 깊이로 덧그립니다(`World`의 안개 층). 하늘은 브라우저판처럼 반지름 380 m 돔, 반구 조명은 주변광과 위·아래 방향광 한 쌍, 가로등은 (1 − 거리/30)²에 맞춘 감쇠, 달빛 그림자는 브라우저판처럼 플레이어 둘레 80 m 상자에 부드러운 그림자(`scripts/moonshadow.gd`). PC에서는 마무리 효과(블룸·채도·비네트, `scripts/grade.gd`)와 주변 가림(AO, `scripts/aoview.gd`)이 브라우저판 최고 품질처럼 들어가고, 프레임이 50 아래로 떨어지면 브라우저판 품질 사다리처럼 AO가 꺼졌다가 회복되면 다시 켜집니다. 휴대폰은 브라우저판처럼 둘 다 없습니다.
- 컨테이너 옆면의 ISO 번호·규격 번호·회사 표시, 바닥의 "07" 페인트를 브라우저판처럼 텍스처에 그려 넣습니다.

- 연구소(스테이지 3, 3-2): 타일 바닥, 청록 띠와 걸레받이가 있는 패널 벽, 벽의 큰 표지, 우리 둘레의 사선 띠와 바닥 번호, 짚, 관제실 창틀과 모니터, 실험대·표본 탱크·서버 랙·선반 소품, 원숭이 박사의 모습과 몸짓.
- 사바나(스테이지 3-1): 마른 풀 바닥과 바퀴 자국 난 흙길(브라우저판처럼 조각마다 기울기가 뒤집혀 지그재그로 보입니다), 해, 울타리, 표지판, 우산 모양 아카시아·바위·흰개미 언덕·덤불, 십자로 꽂은 풀 다발 3200개, 지평선의 언덕. 감시탑은 판자 무늬 벽과 계단, 대각 가새, 난간, 손잡이, 양철 지붕, '감시탑' 표지까지 브라우저판대로 만들었습니다. 풀 다발은 브라우저판처럼 그림자를 받지 않고 AO가 잎을 어둡게 하지 않습니다.
- 동물: 브라우저판 AnimalKit 그대로(타원체 몸통, 얼룩말·호랑이 줄무늬, 치타 점박이, 기린 무늬, 머리와 턱이 따로 움직이는 축, 발굽). 고릴라는 KongKit의 관절 모델과 자세·걸음새이고, 머리와 가슴의 맞는 부위가 자세를 따라 움직입니다.
- 길쭉하게 늘린 원뿔·원기둥(소나무, 나무줄기, 말뚝)은 한 메시로 미리 구워 그립니다. Godot의 멀티메시는 늘린 인스턴스의 법선을 그대로 돌려서 옆면이 하늘을 향한 것처럼 빛나기 때문에, three.js처럼 역전치로 돌린 법선을 넣습니다.

## 브라우저판과 다른 것

- 생김새: 로봇과 우주선은 아직 상자 몇 개로 단순하게 그렸습니다(사람, 좀비, 동물, 고릴라, 마을, 연구소, 사바나와 손에 든 총 8종·부착물은 브라우저판 모양 그대로입니다). 크기, 맞는 부위, 충돌은 브라우저판 값 그대로입니다.
- 스테이지 5에는 컷신이 없습니다(낙하산으로 내려오며 시작하고, 깨면 바로 결과가 나옵니다). 보스 소개에서 황금꿀벌드론의 날개가 따로 움직이지 않습니다(생김새를 맞출 때 함께 고칩니다).
- 먼 적을 단순하게 그리는 처리(브라우저판의 `setFar`)가 없습니다. 성능을 재 보고 필요할 때만 넣습니다.
- 휴대폰 세로 화면에서 브라우저판은 3D 화면을 위쪽에만 그리고 아래를 조작판("YRD-07 휴대 단말")으로 씁니다. Godot판은 3D 화면을 꽉 채우고 버튼을 그 위에 놓으며, 해독약·타기·열쇠·내리기 버튼은 버튼끼리 겹치지 않도록 왼쪽 방향키 아래에 둡니다. 일시정지 버튼은 브라우저판처럼 42 px로 그리되 누르는 범위는 50 px입니다.
- 소리는 브라우저판의 합성 소리를 미리 파일로 만들어 둔 것입니다(`tools/make_sounds.py` → `sounds/`).
- 모든 스테이지를 처음부터 할 수 있습니다(브라우저판은 앞 스테이지를 깨야 다음 스테이지가 열립니다).
- 스테이지 5는 브라우저판에 없습니다. 깬 기록은 저장 코드에 담기지 않고(저장 코드의 스테이지 자리가 8개뿐입니다), 도감에도 장난감 적은 없습니다(도감은 브라우저판의 것 그대로입니다).
- 안드로이드 앱은 만들지 않았습니다(앱 업데이트 중단). 웹 내보내기만 있습니다.
- 달빛 그림자: Godot 호환 렌더러는 그림자 있는 조명을 따로 그려 sRGB로 더하기 때문에, 달빛은 그림자 없는 조명으로 그리고 그림자는 직접 만든 깊이 지도로 화면 위에서 빼냅니다. 적·동물·로봇·전리품과 사바나의 풀·울타리·표지판·물웅덩이·먼 언덕은 브라우저판처럼 그림자를 받지 않습니다(스텐실로 표시해 그림자 층이 건너뜁니다). 그림자 속에서 빼는 달빛 번들거림은 바닥 아스팔트에 맞춘 어림값입니다. 그림자 지도는 PC 2048(브라우저판 최고 품질은 4096), 휴대폰 1024입니다.
- 사바나 풀: 브라우저판은 풀 카드를 AO 깊이 그림에 넣어 둘레 땅을 0.3만큼만 가리게 하는데, Godot에서는 그 표시를 AO 계산보다 먼저 그릴 수 없어서 풀을 AO 깊이 그림에서 빼고 풀 픽셀만 AO를 건너뜁니다(풀 밑동 둘레 땅이 아주 조금 덜 어둡습니다). 풀잎 그림의 투명한 곳은 잎의 평균색으로 채워(투명도는 그대로) 멀리 있는 풀이 검게 얼룩지지 않게 했습니다. 브라우저판은 4배 MSAA의 알파 투 커버리지로 이 얼룩이 섞여 보이지 않습니다. 휴대폰에서도 잘라 내는 기준은 0.3입니다(브라우저판 휴대폰은 0.5).
- AO는 브라우저판과 같은 계산(반 해상도 깊이, 12개 표본)이지만 흐리게 하는 단계를 가로 7, 세로 7 두 번 대신 7×7 한 번으로 하고(픽셀 위치에 따라 가중치를 이어지게 바꿔 선형 확대를 흉내 냅니다), 반투명한 것(입자, 가로등 원뿔, 바닥 빛)은 AO가 들어간 뒤에 그려 어두워지지 않습니다. 블룸은 밝은 부분을 먼저 고른 뒤 흐리는 브라우저판과 달리 화면 밉맵을 흐린 뒤 고르므로 작은 빛의 번짐이 조금 약합니다.
- 스테이지 5(Godot판에만 있는 방)는 원래 만든 빛 그대로 둡니다(Godot 기본 톤 매핑·그림자).

## 만들기와 시험

```bash
GODOT=/path/to/godot ./tools/build_godot.sh     # build/godot-web, build/godot-artifact, 그리고 ../godot-web(GitHub Pages)
godot --headless --path godot res://tests/run.tscn   # 브라우저판에서 뽑은 기준 자료와 비교
godot --headless --path godot res://tests/fight.tscn # 스테이지마다 자동으로 싸워 보기 (1분 남짓)
node tests/dump_reference.js                    # 기준 자료(godot/tests/reference_stage1.json)를 브라우저판에서 다시 뽑기
```

시험(343개)은 브라우저판에 있는 8개 스테이지마다 충돌 상자·나무 상자의 위치와 길 찾기 격자, 적·동물·로봇의 자리와 종류를 브라우저판 기준 자료와 비교하고, 같은 키 입력의 이동 결과, 무기 8종의 모든 수치, 방아쇠를 누르고 있을 때 남는 탄 수, 가만히 서 있을 때 체력이 깎이는 속도, 저장 코드가 브라우저판과 같은지, 그리고 상점·편성·추천 스펙·커스텀, 작전 지도, 컷신, 저장 코드 메일, 도감, 화면 표시와 효과(피해 방향, 체력 경고, 심장 소리, 화살표, 번쩍임, 입자 수)와 스테이지별 규칙(감염, 출혈, 탑승, 감시탑, 문과 세이브 포인트, 보스 페이즈)을 확인합니다. 스테이지 5는 브라우저판 기준 자료가 없어서 장난감 방의 길(계단, 스프링, 투석기, 줄자, 기차)과 장난감 네 종류의 재주(위장, 이단 점프와 활강, 가속과 들이받기, 배터리 나눔과 스파크, 블록 떨어뜨리기·줍기·벽 쌓기·벽 타기)를 따로 확인합니다.
